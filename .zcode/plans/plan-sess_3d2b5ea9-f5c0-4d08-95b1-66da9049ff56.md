# План: Оптимизация ответа RAG (пункт 2)

## Цель
Ответ формируется на основе **авторских определений + ключевых слов Школы** (буст), а при конкретном вопросе клиента выдача сужается по **контексту вопроса** (тема жизни). Без embeddings/внешних реранкеров — только BM25 + авторские правила (в рамках PRINCIPLES/ROADMAP).

## Анализ: почему НЕ гибридный поиск / внешний реранкер
- **Embeddings/векторы** вредны для авторской системы: Школа использует нестандартные управления (Плутон=Весы, Уран=Стрелец), смысловой поиск тянет общеастрологический шум (Плутон=трансформация), который `FORBIDDEN` блокирует. Плюс нарушает ROADMAP (❌ платные embeddings).
- **Внешний cross-encoder** = новый API, деньги, задержка, зависимость — против принципа простоты.
- **Структурированный контекст уже есть**: `inject_context_blocks` поднимает AUTHOR_DEFINITIONS + ASTRO_TERMS в начало контекста, а SYSTEM_PROMPT содержит «Алгоритм анализа» (планета=функция, знак=качество, дом=сфера, аспект=взаимодействие).

**Вывод:** задача решается подключением уже написанного, но спящего кода + точечная правка `main.py`. Новых подсистем не строим.

## Изменение 2 — `core/rag/engine.py`: детектор типа запроса + формирование «Задачи»

Новый метод `build_task_hint(query)` на основе существующего `parse_chart(query)` (планеты/знаки/дома/аспекты) и темы вопроса. Возвращает строку задачи вместо жёсткого «Комплексный анализ по всем сферам»:

| Что в запросе | Задача (вместо «по всем сферам») |
|---|---|
| 1 планета + 1 знак | «Анализ ситуации: функции планеты через качества знака» |
| 2+ планет + аспект | «Анализ взаимодействия планет через аспект» |
| + дом(а) | «Анализ в контексте сферы жизни: {название сферы по AUTHOR_DEFINITIONS дома}» |
| + тема жизни (love/money/health/spirit) | «Анализ в контексте вопроса: {тема}» |
| только общий разбор | «Комплексный анализ» (как сейчас) |

Это прямо реализует вашу логику: «планета в знаке → разбор ситуации; 2 планеты + аспект → анализ с учётом аспектов; + дом → анализ в контексте сферы; + конкретный вопрос → по контексту вопроса».
